# NYC311 Pulse — Case study

## Problem

An operations analyst opening millions of 311 rows does not need another generic dashboard. They need a short, defensible queue: where did an observed pattern move outside its own history, what evidence triggered the alert, what is uncertain, and what should be checked next?

NYC311 Pulse implements that workflow as a fixed historical portfolio snapshot. The language is deliberately observational. A high request count can reflect reporting behavior, intake channels, duplicates, seasonality, category changes, real service conditions, or several factors at once.

## Product decision

The primary object is a `Signal`, not a request. A stable ID is derived from type, district, problem, and detection window. Ranking is deterministic: anomaly strength 50%, affected count 30%, persistence 20%. A map click, filter change, and browser navigation all update the same URL state.

## Data and privacy

The source window is 2024-08-01 through 2026-07-31, fixed at the 2026-08-21 extraction. The artifact records 7,498,437 requests. Request-level extraction is restricted to IDs, timestamps, organizational/category fields, status, district, and intake channel. The public artifact contains aggregates only.

Addresses, streets, coordinates, and free-text resolution fields are never extracted. The map uses 59 official Community District polygons. Joint Interest Areas and unspecified districts remain quality limitations but do not enter the mapped ranking.

## Detection method

The selected model uses the preceding 26 matching weekdays to estimate a conditional count mean and overdispersion. A candidate must exceed the resulting Negative Binomial prediction boundary as well as minimum ratio, baseline, and excess-count gates. Nearby daily detections are merged into seven-day alert episodes.

The validation benchmark also retains 8/13/26-week median/MAD detectors and a hybrid NB/EWMA detector as explicit comparators. Selection happens on January–April 2026 validation data; May–July remains a locked reporting split.

## Evaluation result

The original 0.057 result was invalidated after an extraction audit found that an unpaginated 50,000-row Socrata response stopped on 2026-07-18 while later dates were silently completed as zero. Method 2.0 paginates nine pages, verifies full 2024-08-01–2026-07-31 coverage, rejects duplicate aggregate keys, and reconciles grouped totals against an independent count query before any zero fill.

The selected `nb_conformal-h26-z3.5-d10` model was measured once on 1,200 locked event episodes generated by both Negative Binomial and weekly block-bootstrap controls. It achieved precision 0.846, recall 0.802, F1 0.823, 4.45 false episodes/week, and zero-day median delay. Scenario recall was 0.790 for spikes, 0.838 for level shifts, and 0.777 for gradual ramps, so every synthetic gate passed.

This does not yet make the public product validated. A seeded 60-case review packet mixes the Top-20, 20 near-threshold candidates, and 20 matched controls in blinded order. Until that review reaches Precision@20 ≥ 0.65, every candidate remains `research_flag` and the release state remains `revalidation_required`.

## Engineering decisions

- A resilient Socrata client handles tokens, paging, exponential backoff, checkpoints, and typed validation.
- dbt builds request facts, daily metrics, closure cohorts, open-age inventory, and a quality mart.
- FastAPI serves a read-only artifact and structured 404, 422, and 503 envelopes.
- TypeScript API types are generated from FastAPI OpenAPI and checked in CI.
- The UI consumes the FastAPI snapshot when configured and keeps a build-time snapshot fallback. An API failure changes status without removing the usable queue.
- MapLibre renders district aggregates only. Vega charts always ship an equivalent HTML table.

## Known limits and next work

The aggregate snapshot evaluates the twelve highest-volume training-period problem categories; the total request count covers the full dataset. The validated synthetic claim applies to actionable benchmark strengths—2.75–5× one-day spikes, 1.75–2.5× level shifts, and gradual ramps ending at 1.75–3×—not to every small change. Closure-probability and aged-open code paths remain descriptive. Cross-district differences must not be interpreted as agency quality because sample size and case mix differ.
